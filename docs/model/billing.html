Billing: visits to money

We build the invoices ourselves from visits. ION remains the source of service facts and the pricing referee during migration; QuickBooks holds the issued invoice and returns the line ids we track back onto every visit.

The decision and what it deletes

Ruled Self-build. The old write-ahead promise, ION invoice matching, and expected-vs-actual gates existed only to audit ION's invoices — gone. The Reconciler survives with a new job: do we agree with ION on labor pricing, and is every billable consumable a line on our invoice.

Object model

aggregate root — consistency boundary entity value object (dashed) domain service ◆— composition (owned child)    - - → id reference, never an object graph
Backrefs are the tracking backbone When a line is added and later issued, QBO's echo (invoiceId, docNumber, qboLineId) is written back onto the visit / usage. "Where was this billed" is a column read — never a join hunt.
